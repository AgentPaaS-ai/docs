# AgentPaaS v0.3.7 release notes

Release date: 2026-08-07

This release adds cloud pull, cloud cron controls, and read-only schedule and usage views.

## Breaking changes

None recorded for this release.

## Upgrade notes

Install or upgrade the Homebrew cask, then restart the daemon:

```bash
brew update
brew upgrade --cask AgentPaaS-ai/homebrew-tap/agentpaas
agentpaas version
agentpaas daemon stop 2>/dev/null || true
agentpaas daemon start
agentpaas doctor
```

Use the output of `agentpaas version` to confirm the CLI and daemon versions. The Cloud login flow requires you to open the approval URL in the browser you used to claim the trial.

## Added

- Cloud cron commands: `agentpaas cloud cron set`, `disable`, `enable`, and `list`.
- Named cloud cron intervals: `every_1m`, `every_5m`, `every_15m`, and `every_1h`.
- Five-field UTC cron expressions, such as `30 9 * * 1-5`.
- `agentpaas cloud pull`, which creates a metadata-first local project for the edit, pack, push, and redeploy loop.
- Browser login coaching through `agentpaas cloud login`. Hermes tells you to complete the approval in your own terminal.
- Hermes tools for cloud cron operations.
- Cloud dashboard schedule and usage views. Cron changes still go through the CLI, Hermes, or API.
- Public CLI pages for installation, projects, packing, policy, audits, secrets, identity, trust, cloud commands, and cron.

## Changed

- Cloud cron expressions use UTC. `set` creates or changes the stored schedule and enables it. `disable` stops new scheduled fires while keeping the expression. `enable` resumes the stored expression.
- `cloud pull` is metadata-first. It can produce a stub project when the richer source archive is unavailable. Keep the original local project or signed package when you need the complete source.
- Trial onboarding is invite-based. The dashboard is primarily a verification surface for the operations performed by the CLI and Hermes.

## Deprecated

None recorded for this release.

## Removed

None recorded for this release.

## Fixed

- Fixed the cloud pull and cloud login plugin contract so the new commands work through the Hermes integration.
- Fixed the customer documentation links for the CLI and Cloud guides.
- Fixed the successful-invoke documentation so an empty Logs view is explained instead of treated as a missing run.
- Fixed stale onboarding language around the LLM provider picker and the cloud login approval flow.

## Security

- The managed trial vault is a preview backend. The release does not make OpenBao-grade isolation claims.
- Cloud cron changes are tenant-scoped. The console lists schedules and the CLI performs mutations.
- Keep LLM keys out of chat and agent source. Use the documented secret flow and bind the credential to the deployment.

## Known issues

- The proven cold trial path uses OpenRouter. Other providers may work when their host is allowed by policy, but they were not stranger-tested for this release.
- `cloud pull` does not guarantee a full source archive. Review the generated metadata and stub before packing again.
- The minimum reliable cloud cron interval became `every_5m` later in the 0.4.0 line. Treat `every_1m` as unsupported when using a current CLI.

## How to use the new features

Set and inspect a five-minute schedule:

```bash
DEPLOYMENT_ID="dep_01JEXAMPLE000000000000000000"
agentpaas cloud cron set "$DEPLOYMENT_ID" --expr every_5m
agentpaas cloud cron list
agentpaas cloud cron disable "$DEPLOYMENT_ID"
```

Use a weekday schedule in UTC:

```bash
DEPLOYMENT_ID="dep_01JEXAMPLE000000000000000000"
agentpaas cloud cron set "$DEPLOYMENT_ID" --expr "30 9 * * 1-5"
```

Start an edit loop from a cloud component:

```bash
agentpaas cloud pull weather-agent --dir ./weather-from-cloud
agentpaas cloud pull weather-agent --bump-version 0.2.0
```

See [Cloud cron](../trial/cloud-cron), [Cloud pull](../trial/cloud-pull), and [Cloud commands](../cli/cloud) for the complete procedures.
