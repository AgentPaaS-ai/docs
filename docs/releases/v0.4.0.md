# AgentPaaS v0.4.0 release notes

Release date: 2026-09-07

The v0.4.0 tag is a CLI and daemon release. Its feature line was assembled from 2026-08-12 through 2026-09-07. The Cloud repository has no matching v0.4.0 tag, so the Cloud items below describe the Cloud state associated with the v0.4.0 CLI line.

This release moves the platform from single agent deployment toward a component registry, MCP and tool deployments, signed workflows, hosted runs, and inspectable Cloud objects.

## Breaking changes

- Cloud undeploy is a destructive operation. It requires `--yes`. In a non-TTY, it also requires `--confirm-id` equal to the deployment ID. In a TTY, the CLI asks you to type the deployment ID even when `--yes` is present.
- Cloud cron accepts five-field UTC expressions, but current validation floors the usable interval at `every_5m`. A one-minute schedule is rejected by current CLI and Cloud validation.
- HTTP is the supported transparent-proxy model. Non-HTTP protocols require an explicit supported integration path.

## Upgrade notes

Install the v0.4.0 cask and restart the local daemon:

```bash
brew update
brew upgrade --cask AgentPaaS-ai/homebrew-tap/agentpaas
agentpaas version
agentpaas daemon stop 2>/dev/null || true
agentpaas daemon start
agentpaas doctor
```

On macOS, the installer may need Docker Desktop or Colima. If macOS quarantine blocks the binaries, clear quarantine on the installed binaries and run `agentpaas doctor` again.

Pack Cloud images for `linux/amd64`:

```bash
agentpaas pack ./my-agent --target linux/amd64
```

## Added

- Component Registry entries for agents, MCP servers, and tools.
- Cloud deployment of tools with `agentpaas cloud deploy --type tool`.
- MCP server deployment with package kind `mcp_service`.
- Signed workflow envelopes with linear, fan-out, choice, and phone-call workflow kinds.
- Workflow creation, composition, listing, inspection, start, instance inspection, live-call, and hangup commands.
- Cloud workflow and run views in the console.
- File inputs up to 50 MiB at the workflow boundary and API request bodies up to 10 MiB.
- Stage file pointers and handoff artifacts for multi-stage runs.
- Bounded transient retry, up to three attempts where the stage policy permits it.
- Invoke tokens for direct Cloud invocation and Streamable HTTP MCP access.
- Cloud pull metadata for the local edit loop.
- Webhook and completion or delivery paths through the API.
- Registry inspection and search commands.
- Publisher and component metadata in inspect and run status output.
- Optional `--callee` values on Cloud deploy for signed delegation configuration.

## Changed

- The Cloud console is read-only for most operational changes. Use the CLI, Hermes, or the HTTP API to create, deploy, invoke, schedule, and change resources.
- A workflow is a signed recipe. It is not live compute. Deploy its member components before starting a workflow.
- A component image must be admitted to the Cloud registry before deployment.
- Cloud input URLs require the destination host to be declared in the packed component policy.
- MCP `tools/call` errors produce failed runs. The MCP runtime uses the `mcp_service` path when the package declares that kind.
- HTTP Basic credentials are encoded by the platform from the brokered `user:pass` value. Keep credentials in the brokered secret path.
- Google Drive and Docs share links are rewritten to export URLs before fetch when the input path supports them.

None recorded for this release.

## Removed

None recorded for this release.

## Fixed

- Fixed Homebrew installation on macOS when quarantine or a restricted `PATH` prevented the CLI from finding its dependencies.
- Fixed GitHub installation so the local Docker or Colima runtime starts before health checks.
- Fixed `cloud status` to show the component name from the signed image metadata.
- Fixed cloud push and deploy progress and raised the plugin timeout for long image operations.
- Fixed MCP `tools/call` result classification and error propagation.
- Fixed MCP header authentication and support for keyword arguments in tool calls.
- Fixed workflow JSON file opening to reject unsafe symlink paths.
- Fixed signed egress validation so an overlay cannot grant more network access than the signed policy.
- Fixed live-call retry behavior while a child waits for a seat.
- Fixed HTTP redirect handling and 3xx classification in outbound live-call hops.

## Security

- The signed package carries publisher identity, component metadata, and policy data. A valid signature proves package integrity and publisher identity. It does not prove that the component is safe.
- Local multi-stage execution remains fail-closed. The local runtime trusts the developer's machine.
- Cloud default-tier policy enforcement occurs at the egress boundary. Substrate-enforced isolation belongs to the paid, on-request high-assurance tier.
- AgentPaaS contains blast radius. It does not prevent prompt injection.
- The preview vault remains a preview backend. This release does not make OpenBao-grade isolation claims.

## Known issues

- Native HITL, join-any, for-each, wait or delay, deeper workflow spawning, and local multi-stage runs are unavailable.
- Workflow stages are limited to 32. Fan-out is limited to 64 copies. Transient retry is limited to three attempts.
- A standalone agent-to-agent call must be declared in the signed workflow or delegation snapshot. An undeclared call fails closed.
- A URL input fails when its host is absent from the packed policy.
- The trial capacity is limited to 10 live deployments and 5 concurrent runs. A workflow with three deployed members consumes three deployment slots.
- A workflow run can fail with `deployment_not_found` when a referenced member deployment has been removed. Redeploy the member and restore its bindings.

## How to use the new features

Deploy a tool:

```bash
agentpaas pack ./my-tool --target linux/amd64
agentpaas cloud push --lock ~/.agentpaas/state/agents/my-tool/agent.lock
agentpaas cloud deploy latest --type tool
```

Inspect the registry and deploy a workflow member:

```bash
agentpaas cloud registry
agentpaas cloud workflow compose --name support-flow --compose ./compose.json
agentpaas cloud workflow list
```

Mint an invoke token and call a deployment:

```bash
DEPLOYMENT_ID="dep_01JEXAMPLE000000000000000000"
agentpaas cloud invoke-token "$DEPLOYMENT_ID"
agentpaas cloud invoke "$DEPLOYMENT_ID" --body '{"query":"weather in Folsom"}' --wait
```

Call an MCP deployment through Streamable HTTP with the deployment invoke token:

```text
DEPLOYMENT_ID="dep_01JEXAMPLE000000000000000000"
INVOKE_TOKEN="inv_01JEXAMPLE000000000000000000"
https://cloud.agentpaas.ai/v1/deployments/$DEPLOYMENT_ID/mcp
Header: X-Agentpaas-Invoke-Token: $INVOKE_TOKEN
```

See [Workflows](../trial/workflows), [MCP servers](../trial/mcp-servers), [Tools](../trial/tools), [Invoke tokens](../cli/invoke-tokens), and [Platform limits](../trial/platform-limits).
