# Release 0.4.1

AgentPaaS 0.4.1 adds the cloud ingress source and connection model for third-party events that start governed runs. A source has a provider, signing secret, Request URL, and lifecycle. A connection subscribes a deployment to that source and can filter events before a run is admitted.

## Ingress providers

The release includes provider adapters for:

- `slack`, for Slack Events API `app_mention` events, Slack request verification, and optional threaded replies
- `stripe`, for Stripe-style `t=...,v1=...` signatures
- `github`, for GitHub `X-Hub-Signature-256` signatures and delivery IDs
- `generic_hmac`, for services that can send the documented HMAC-SHA256 request format

Ingress verifies HMAC before a run exists, applies connection filters, deduplicates provider event IDs where available, and records ingress event status. It uses the deployment's existing invoke limit.

## Slack setup

Create a Slack source and connect it to a deployment with the CLI:

```bash
printf '%s' "$SLACK_SIGNING_SECRET" | agentpaas cloud ingress source create \
  --provider slack \
  --label "support bot" \
  --secret-stdin

agentpaas cloud ingress connect src_01J... dep_01J... \
  --label "reply to support mentions" \
  --filter '{"match":"all","rules":[{"field":"event.channel","op":"eq","value":"C0123"}]}'
```

Paste the printed Request URL into the Slack app's Event Subscriptions configuration and subscribe to the `app_mention` bot event. Bind an `xoxb-` bot token as `slack-bot-token` when the agent should reply in the originating thread.

See [Ingress through the gateway](../trial/ingress) for the Slack walkthrough, filter operators, source lifecycle commands, reply setup, supported provider behavior, and failure modes.
