# Release 0.4.2

AgentPaaS CLI 0.4.2 adds lifecycle commands for admitted cloud resources. Every destructive command requires an explicit `--yes` flag. In a non-TTY, pass `--confirm-id` with the exact resource id, name, or digest. In a TTY, the CLI asks you to type the same value, even with `--yes`.

## Cloud lifecycle commands

Delete an admitted image by image id or `sha256:` digest:

```bash
agentpaas cloud images delete <img_or_sha256> --yes --confirm-id <img_or_sha256>
```

Delete a cloud secret label:

```bash
agentpaas cloud secrets delete <name> --yes --confirm-id <name>
```

Use `--force` when the secret is still bound to deployments and you intend to remove it. Secret values are never printed.

Retire a stored workflow recipe:

```bash
agentpaas cloud workflow retire <wf_id> --yes --confirm-id <wf_id>
```

Retirement returns HTTP 409 while workflow instances are still running. Stop or hang up those instances before retrying.

Delete an ingress source:

```bash
agentpaas cloud ingress source delete <src_id> --yes --confirm-id <src_id>
```

The source deletion does not disable connections. If enabled connections still reference the source, the CLI reports the connection ids and the disable command to run for each one.

The existing deployment command also uses the destructive confirmation flow:

```bash
agentpaas cloud undeploy <dep_id> --yes --confirm-id <dep_id>
```

Undeploying deletes live compute, removes that deployment's secret bindings, and frees its slot. A workflow that refers to the deployment remains stored. Its later run fails with `deployment_not_found` until the component is deployed again and its bindings are restored.

See [Cloud commands](../cli/cloud) for HTTP 409 behavior and the full command reference.
